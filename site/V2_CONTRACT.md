# V2 UI / assembler handoff

Status: extension contract ready for assembler. UI owner changes only site UI, docs, tools and tests; assembler owns data, downloads, assets and assembly code. Preserve every existing document ID, question, source image, PDF and audit/hold flag from release 9344cc6. No deployment is part of this work.

## Compatible schema

Keep `schema_version: 1`. All V1 fields remain supported. Final inventory is a **minimum 15 official + 4 practice + 2 notes**, not a maximum of 21. Every added document receives the same structural, provenance, evidence and answer validation as existing documents.

Optional fields on documents:
- `collection_type`: `pyq`, `sqp`, or `mixed`; only on `kind: "official"`. A pyq/sqp collection must contain only official questions whose `exam_type` is respectively `PYQ`/`SQP`. Mixed collections may contain both. Existing documents without this field are classified from referenced questions for display, not mutated.
- `collection_scope`: `compilation`, `master`, or `year`; only on official documents. Master and year collections appear in the dedicated large chapter collections area. Omitted means compilation.
- `year`: string or number, required for `collection_scope: "year"`; must match each included question's year or session. Multi-year master banks omit it.
- `pdf_pages`, `pdf_bytes`: optional positive integers describing the actual generated PDF. Omit until measured. UI displays supplied values; validation cannot certify PDF layout or content.

Suggested new stable IDs: `pyq-master`, `sqp-master`, `pyq-year-2025`, `sqp-year-2025-26`. These are naming suggestions, not published records. Use the existing `pdf` path field only after a chapter PDF exists. Never substitute full Science source PDFs for chapter compilations. No new PDFs or official sample records are generated by the UI.

Question browsing uses authoritative `exam_type`, `year`, `session`, and `paper_code` (optional `set` fallback). Missing values are not inferred from filenames/titles. Question IDs and original question numbers remain visible. Original practice and notes remain separate.

## Special39 original practice

Use `kind: "practice"` and optional `practice_series: "special39"`. The UI also recognizes Special39 in a supplied title and stable IDs `special-39-01` through `special-39-04` for compatibility. Only practice documents qualify. These cards appear first in a bordered **Special39 / competency practice** group within Original practice; other original papers remain separate. Supplied titles are preserved. Card question counts come only from `question_ids.length`, never from the series name or anticipated author totals. Missing papers are not fabricated. Status, PDF availability and question/answer verification remain authoritative data fields. Original editorial notes are disclosed with answers and excluded from questions-only print.

The anticipated 27-document / 298-question release requires separate assembler validation and visual review; the UI recovery does not publish or certify that dataset.

## Optional coverage ledger

Preferred compact extension: `coverage.source_ledger` is an array of rows with required `id` (unique nonempty string), `exam_type` (`PYQ`/`SQP`), `year` (string/number), `status` (nonempty plain text). Optional `session`, `set`, `note` are plain text; `source_url` is a safe citation URL; `reviewed`, `exhaustive` are booleans; `published_questions`, `verified_questions`, `held_questions` are nonnegative integers. Counts describe distinct records under a disclosed counting rule, not additive marks. False and zero are meaningful and must remain visible. Status is an assembler claim, not UI certification. No automatic promotion from downloaded to reviewed or verified.

If supplied, the UI displays this ledger. Without it the UI displays a bounded summary from the existing `coverage.source_inventory.pyq` year records and `coverage.source_inventory.sqp.documents`, clearly separating research inventory from published question counts. Existing coverage limitations and answer holds remain intact. Research-only filesystem paths are never made into download links.

## Reader and performance

PDF embeds are opt-in and removed when closed/switched; open/download fallback links remain available. Large document question readers are paginated; full document printing remains explicit. Original image assets are reused unchanged with a zoomable full-window dialog and Escape close. No preloading every PDF/image.

## Assembler acceptance

Run `node tools/validate.mjs` and `node tools/validate.mjs --final` from site. Preserve the existing 21 documents and content; add collections, do not replace them. Validate collection purity and actual file existence, source holds, nonadditive choice accounting and PDF page readability independently. UI checks do not replace editorial/source audit.
